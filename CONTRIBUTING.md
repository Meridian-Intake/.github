# Contributing to Meridian Repositories

Meridian repositories are operated as controlled, privacy-aware workspaces for intake infrastructure and public-facing documentation.

## Contribution Principles

- Prefer clear, reviewable changes over large unstructured edits.
- Keep regulated-domain boundaries explicit: no legal advice, medical advice, diagnosis, treatment recommendations, or professional judgment.
- Do not commit secrets, credentials, client records, transcripts, patient data, privileged material, or sensitive operational details.
- Document meaningful process, architecture, security, or policy changes near the affected artifact.
- Use pull requests for all changes to protected branches.

## Pull Request Expectations

Every pull request should include:

1. A concise summary of the change.
2. The audience or operational purpose.
3. Validation performed, such as link checks or Markdown preview.
4. Privacy and regulated-boundary confirmation.
5. Any follow-up work or known limitations.

## Documentation Style

- Write in plain, procurement-friendly language.
- Distinguish current capabilities from roadmap items.
- Avoid hype, unverifiable claims, and ambiguous automation promises.
- Use checklists for operational procedures and decision gates.
- Prefer evidence, controls, and accountability language.

## Review Standards

Reviewers should check that changes are:

- Accurate and consistent with Meridian's positioning.
- Safe to publish publicly.
- Clear about scope, ownership, and operational boundaries.
- Aligned with privacy, security, and human-oversight expectations.
